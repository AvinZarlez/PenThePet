# Contributing to Pen the Pet

Thank you for your interest in contributing to Pen the Pet! 🐾

---

## 🐛 Found a Bug?

If you run into something that doesn't work as expected, please [open a bug report](https://github.com/AvinZarlez/penthepet/issues/new?template=bug_report.md). Include as much detail as you can — steps to reproduce, what you expected, and what actually happened. Screenshots are always helpful!

## 💡 Have a Feature Idea?

Got an idea for a new feature or improvement? [Open a feature request](https://github.com/AvinZarlez/penthepet/issues/new?template=feature_request.md) and describe what you'd like to see. All suggestions are welcome!

## 🔧 Want to Fix a Bug or Build a Feature?

If you'd like to tackle an existing [bug or feature request](https://github.com/AvinZarlez/penthepet/issues), feel free to do so! Here's how:

1. **Check the issue list** — look for open issues labeled `bug` or `enhancement`.
2. **Comment on the issue** to let others know you're working on it.
3. **Fork the repository** and create a branch for your change.
4. **Follow the development setup** described in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
5. **Run tests** with `npm test` and make sure everything passes before submitting.
6. **Open a pull request** — describe what you changed and why.

## 📋 Development Guidelines

- No frameworks or libraries — vanilla HTML, CSS, and JavaScript only.
- Use `CONSTANTS`/`CONFIG` from `constants.js`/`config.js` — never hardcode values.
- All tests must pass and coverage must stay above thresholds (`npm test`).
- Run the linter before submitting (`npm run lint:fix`).
- See [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) for the full development setup guide.
- See [docs/TESTING.md](docs/TESTING.md) for how to write and run tests.
